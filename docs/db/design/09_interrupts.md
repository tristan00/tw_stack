# 9. Interrupts

## 9.1 Corrected model

An interrupt is a snapshot (`corpus.snapshot.kind = interrupt`) with its own `snapshot_id`, `campaign_id`, `ts` (= the launcher's choice time), `turn` (captured at panel time), `version_id`, plus:
- **its own captured state** in `snapshot_campaign` (the 19 `_parse_campaign` scalars + `eval_ms`) and `snapshot_world` / `world_army` / `world_hostile` / set ids for regions, settlements, ruins, enemy_agents — captured by the launcher **immediately before the click** (`state_at = panel`), so the row answers "what did the game look like when the panel was up"; migrated rows carry `state_at = recorder` (the post-click, post-drain state the recorder sampled, R4 C.2);
- **`prev_decision_id`**: the decision snapshot the chooser scored against (latest decision with `ts ≤ ts_choice` in the campaign) — the state training and serving actually use (R4 H.2, R2 F.31-32);
- the screen (`kind`, `root`, `dilemma_id`/`incident_id`, `root_context`, `region_id`), the options (`interrupt_option`: ordered, keyed, with the chooser's per-option `exploit`/`score`/`gnn`, `text`, `option_id`, `answer`, `payload`), the choice (`chosen`, `answer`, `policy_id` NULL when no chooser ran), the outcome (`executed`, `confirmed`, `counted`, `refusal_id`, `latency_ms`), and the typed panel facts (`interrupt_battle_panel`, `interrupt_diplo_panel`).

Record production (launcher, `interrupts._record_choice`): before `_click`, `cs = collect.campaign_state(bus)`, `ws = collect.world_state(bus)` (both existing functions; the executor owns a `Bus`); after resolution the record is `{kind, root, root_context, options (no subtree), chosen, answer, executed, confirmed, counted, refusal, latency_ms, policy, scores, panel (retained keys), ts_choice, campaign: cs, world: ws}`. The recorder stores it verbatim (07 U4). Cost per interrupt: one extra `campaign_state` + `world_state` eval on the launcher bus (ASSUMPTION ≈ 100-200 ms; 14 lists the measurement); at 0.21 interrupts/decision that is ≤ 40 ms/decision amortised, outside the recorder's `store_ms`.

## 9.3 Integrity rules on the interrupt tables

- `interrupt_option UNIQUE (interrupt_id, option_key)`; `interrupt.chosen` must be one of the row's option keys — checked by the writer (0 mismatches in 8,679 sampled rows, R4 B.1) and by a verification query, not by a cross-row constraint.
- `counted = executed AND confirmed` when all three are non-NULL (CHECK in 03a); NULL only for `confirm_unreadable_bus_failure` (3 rows).
- `prev_decision_id` NULL is legal only for interrupts before a campaign's first decision (the opening screens of turn 1); the writer resolves it with the Q-ST query in the same transaction.
- Panels: exactly one of `interrupt_battle_panel`/`interrupt_diplo_panel` rows per interrupt, or none, by kind (writer rule; verification query).

## 9.4 Migration of interrupts (10 §10.5 step M4)

Per legacy row: `snapshot` (kind interrupt, `ts` = old ts, `turn` = old turn, `version_id` = the version of the latest decision with `ts ≤ old ts` in the campaign, else the sentinel `legacy:meta1:pq1` — the ICB key set has no version-dependent keys, R4 B.3), `snapshot_campaign` from ICB (19 keys + `_eval_ms`), world tables from IWB (6 keys; 6 rows with NULL world get no world rows and `snapshot_world` NULL columns), `interrupt` (`state_at = recorder`, `prev_decision_id` by Q-ST, `dilemma_id`/`incident_id` by stripping the `CcoCdirEventsDilemmaChoiceDetailRecord` prefix from `root_context` and resolving against `dict.dilemma`/`dict.incident`, else a non-reference `dict.dilemma` row), `interrupt_option` from `options_json` (keys in JSON key order → `ord`; `subtree` dropped; `context` kept), panels by kind from `panel_blob`. Round-trip validation for interrupts (12): ICB and IWB canonical-form exact (02 2.9, both sides normalised); options/panels over the retained projection.
