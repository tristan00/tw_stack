# 14. Assumptions and open questions

Only things the evidence cannot settle. Each has the cheapest experiment; none is a decision left to the owner — the design's choice stands unless the experiment contradicts the stated bound.

| # | assumption | used in | cheapest experiment | consequence if wrong |
|---|---|---|---|---|
| A1 | Python-side cost of normalise + canonical encode + ≈ 60 SHA-256 per decision ≈ 3-5 ms | 05 Q-W1, 06, 10.6 | 13 §0.6 dry run on 2,070 decisions; time the encoder alone | if > 10 ms: hash with BLAKE2b (stdlib, ≈ 2× faster) and move encoding of the two largest collections (skills, tech) to a C-accelerated `struct.pack` path; budgets in 12.4 adjust by the measured delta  **SETTLED 0.6: **0.288 ms/record** (15,390 records), 10-17x under the 3-5 ms assumption. No BLAKE2b fallback needed.** |
| A2 | `hydrate.record` assembly ≈ 5 ms/decision in Python (≈ 1,000 objects) | 05 Q-L1, 01 T3 | same dry run: time `hydrate.records` over the sample | if > 10 ms: return `state` dicts with tuple-backed lists (no per-member dict) for training and keep dicts for the live loop only  **SETTLED 0.6: **0.129 ms/record** hydrate from the DB, 39x under the 5 ms assumption.** |
| A3 | fraction of `reach_chars`/`reach_setts` values that are `true` ≈ 50% | 06 char_state row width (36 + 26 B) | `SELECT` 100 lord blobs, count true values | width changes by ≤ 40 B/row (± 22 MB total); no design change |
| A4 | `pg_dump -j 8` + `pg_restore -j 8` of 16.3 GB ≈ 15 min on NVMe | 10.6 | S2 itself (it is the first step; time is logged) | only the downtime estimate changes  **SETTLED 0.6: dump 76 s + restore 113 s = **189 s** for 15 GB, not 15 min. Row counts equal on all 199 tables.** |
| A5 | COPY binary ≥ 300k rows/s and 3-way join read ≥ 150k rows/s per worker for offers | 10.6 S7 | dry run S7 on the 1% sample | only the downtime estimate changes  **SETTLED 0.6: **343,963 - 371,582 rows/s** binary COPY (507,590 rows), meets the >= 300k gate.** |
| A6 | reference FK validation ≈ 20 ms per constraint, PK DDL ≈ 15 ms per table | 04 §4.6 (≈ 100 s build) | first full build logs `build_seconds` | budget is 180 s; if exceeded, FK support indexes are built after the FKs (validation uses hash joins anyway) |
| A7 | `collect.campaign_state` + `world_state` on the launcher's bus cost 100-200 ms per interrupt | 09 §9.1 | time both calls in `_record_choice` for 50 interrupts (`stderr` timing line) | if > 500 ms: capture only `campaign_state` at panel time and set `world` from the recorder as today with `state_at = recorder_world` (a third enum value); the schema is unchanged |
| A8 | `synchronous_commit = on` costs < 3 ms per commit on this NVMe | 07 §7.4 | 200 commits each way in the dry run | if < 3 ms the recorder switches it on (removes the crash-loss window); else stays off  **SETTLED 0.6: **no measurable cost** for bulk load -- one commit per COPY batch, so on/off differ by less than run-to-run noise (1,366 vs 1,476 ms, on faster). The per-decision live-writer case is still open; 07 7.4 keeps it off until 1.3 measures 200 commits each way.** |
| A9 | `ref.campaigns` (pack `campaigns_tables`) has a key column usable for `dict.campaign_map` (`wh3_main_combi`, `wh3_main_chaos`); `campaign_post_battle_captive_option_binding` is the junction table name behind `captive_binding` | 03a dict.family, 04 §4.7 | `SELECT key_cols FROM ref.table_meta WHERE tbl IN (...)` after the first build; `grep` of `build_reference.py` for the junction source | rename the `ref_tbl/ref_col` in `dict.family` (data, not schema) |
| A10 | the 3 sentinel collector versions cover every NULL-version decision (no other optional-block combination exists) | 2.5 | migration asserts the observed signature per snapshot (F7); a fourth combination fails the range | add a sentinel row; no schema change |
| A11 | `sample_index` of a move offer equals its position among the entity's move offers, and `reach_rays/reach_max` are identical across an entity's tiles | 2.6, 03a | V2 over the window (100% required) | if violated on old versions only: reported (non-blocking); if in the window: store `sample_index` on `offer` (one SMALLINT) |
| A12 | interrupt-model quality is unaffected by `isc_option_label` now carrying the button key for non-dilemma screens (C.8) | 09 C.8, 12 T2 | first retrain after cutover: compare `val_r2` (today 0.519) | if worse by > 0.02: `_row` keeps `"none"` for those screens (one-line revert); the column stays |
| A13 | `campaign_key` present on every legacy `diplomacy_events` row resolves to a campaign except 65 rows | 07 U5 migration note | count at migration | the 65 get campaign rows created from the key (faction from prefix) with `note`; if the key is malformed, the row is skipped and logged in `migrate.mismatch('M5')` |
| A14 | no reader depends on `taken.confirm_before/after`, `diagnostics.params/execute_error`, panel keys dropped in 03b §3.8, diplomacy payload keys dropped in §3.9, postmortem `turn_tail` etc. | C2 drops | `grep -rn` for each key name over `*.py`, `*.ts`, `*.tsx` (R2/R3 did this for the listed consumers; a final grep before 13 §1.3 confirms) | add the column (all are scalar/text) before migration; no structural change |
| A15 | `options.generate` is deterministic given the record and the live reference (no randomness, no time dependence) | 2.6 | V2 100% in the window proves it for current code; `grep random\|time\.` in `options.py` | if a random tie-break exists, seed it from `decision_uuid` |

Follow-ups deliberately outside this design (recorded, not decided here): retraining the interrupt model on panel-time state (C.3) and excluding refused twins (C.6) are modelling changes; `synchronous_commit` per A8; a `snapshot_id`-range archival at 100 GB (06 §6.4).
