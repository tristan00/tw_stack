# R1 -- corpus write path and the full record shape

Sources: working tree at HEAD (6d18a7f). Live-DB measurements were taken read-only on 2026-09-04 with `statement_timeout` set and id-modulo sampling; every measured number is marked "(measured)". No recorder, advisor or API was connected to `tw_stack` at measurement time (pg_stat_activity showed only my own backend).

## 0. Pipeline in one paragraph

The advisor (`advisor/session.py` -> `advisor/loop.py`, one process) never writes decision rows itself. It inserts a request row into `rpc_requests` and NOTIFYs (`decisions/journal.py:77-83`); the recorder thread `decisions` inside `manager/manager.py` (started `manager/manager.py:323-325`, body `decisions/decisions_stream.py:76-228`) polls `rpc_requests` (`decisions/journal.py:98-111`), collects game state over the file bus (`decisions/collect.py:1671-1865` via `bus/bus.py:292-366` into `bus/mod/twcontrol.lua:495-507, 838-1046`), writes it through `decisions/store.py` and answers via `rpc_responses` (`decisions/journal.py:85-95`). The advisor then reads the stored decision back out of Postgres (`decisions/journal.py:169-187` -> `decisions/store.py:574-587`), generates options, and ships options / pick+scores+timings / verification / interrupts / diplomacy / ucb / postmortem as further `rpc_requests` rows that the same recorder thread turns into `offers`, `offer_scores`, `offer_model_scores`, `decisions.timings`, `taken`, `interrupts`, `diplomacy_events`, `ucb_picks(+rows)`, `postmortems`. `bus/mod/twstate.lua` is NOT on this path (see F.5).

## A. Table by table (`decisions/pg_schema.py`)

Schema version string `pg1` (`pg_schema.py:26`), checked at every store open (`store.py:83-94`). DDL + VIEWS are re-executed by every writable `DecisionStore` open (`store.py:76-80`) and by `decisions/pgbootstrap.py:46-59`; the VIEWS block contains `DROP VIEW IF EXISTS action_offers; CREATE VIEW action_offers` (`pg_schema.py:185-186`) so every recorder start drops and recreates that view; the DDL block also carries two `ALTER TABLE ... ADD COLUMN IF NOT EXISTS adjust` (`pg_schema.py:142-143`).

Only two modules write these tables in the whole tree: `decisions/store.py` and `decisions/journal.py` (grep of INSERT/UPDATE/DELETE over `*.py`; `pgbootstrap.py:51` writes `meta` only).

Connection used by every `store.py` writer: `self.con = pg.connect()` (`store.py:74`) = psycopg3, `autocommit=False` (`pg.py:41-57`), `SET synchronous_commit = off` (`store.py:75`). Every public write method ends in `self.con.commit()`; there is no `rollback()` anywhere in `decisions/` (grep). Transactions are therefore "one per store method call", opened implicitly by the first statement.

### A.1 `meta` (`pg_schema.py:29`)
`k TEXT PK, v TEXT`. Writer: `INSERT ... ON CONFLICT (k) DO NOTHING` at store open (`store.py:78-79`) and db-init (`pgbootstrap.py:51-52`). One row `schema_version=pg1` (measured).

### A.2 `collector_versions` (`pg_schema.py:31-33`)
`version_id BIGINT identity PK, collector_sha TEXT NOT NULL UNIQUE, git_sha TEXT, started_ts DOUBLE PRECISION, note TEXT`. Writer `register_collector` (`store.py:188-199`): `INSERT ... ON CONFLICT (collector_sha) DO NOTHING` + `SELECT version_id`, commit; called once per recorder start when `TW_CODE_VERSION` is set (`decisions_stream.py:105-110`; `git_sha` is parsed out of the `+g<sha>` suffix, `note='code_version'`). `started_ts` is the first registration time only (DO NOTHING). Result cached in `self._version_id` and stamped on every decision (`store.py:229`). 32 rows (measured).

### A.3 `blobs` (`pg_schema.py:35-37`)
`blob_id BIGINT identity PK, sha TEXT NOT NULL UNIQUE, n INTEGER NOT NULL, z TEXT NOT NULL`. Single writer `_blob` (`store.py:110-127`): `SELECT blob_id FROM blobs WHERE sha=%s`, and if absent `INSERT INTO blobs(sha,n,z) VALUES(...) RETURNING blob_id`. No ON CONFLICT (single-writer assumption). Never UPDATEd or DELETEd (no statement in the tree). See C.

### A.4 `actions` (`pg_schema.py:39-43`)
`action_id BIGINT identity PK, context_kind TEXT NN, context_id TEXT NN, action_type TEXT NN, action_key TEXT NN, params TEXT NN, UNIQUE(context_kind, context_id, action_type, action_key, params)`. Writer `_action_id` (`store.py:129-143`): `INSERT ... ON CONFLICT DO NOTHING` then `SELECT action_id WHERE <all five>`; process-local cache capped at 200000 entries then cleared (`store.py:140-141`). Callers: `attach_options` per option (`store.py:260-262`), `attach_taken` when the taken action is not among the decision's offers (`store.py:342-344`). Index `ix_taken_action`, `ix_offers_action` (`pg_schema.py:157-158`). 5,108,439 rows of which 4,888,404 are `move` (measured) -- `params` for `move` holds `reach_rays/reach_max/sample_index/x/y` (see D.1), so nearly every move offer creates a fresh row.

### A.5 `campaigns` (`pg_schema.py:45-51`)
`campaign_id BIGINT identity PK, campaign_key TEXT NN UNIQUE, faction, campaign_map TEXT, presave_radius DOUBLE, selector TEXT, picked_ts DOUBLE, difficulty INTEGER, leader TEXT, first_decision_id, last_decision_id BIGINT, outcome TEXT, defeated SMALLINT, turns INTEGER`.
Writers:
- `_campaign_id` (`store.py:148-186`): cache miss -> `INSERT ... ON CONFLICT (campaign_key) DO NOTHING` + `SELECT campaign_id`; cache hit -> up to five conditional `UPDATE campaigns SET <col>=%s WHERE campaign_id=%s AND <col> IS NULL/''` for campaign_map, presave_radius, selector, difficulty, leader (`store.py:152-176`). These five UPDATEs run on **every** `write_decision` once the cache is warm (all five values are normally non-null), each a no-op after the first.
- `write_decision` (`store.py:241-244`): `UPDATE campaigns SET first_decision_id=COALESCE(first_decision_id,%s), last_decision_id=%s, turns=GREATEST(COALESCE(turns,0),%s)` once per decision.
- `write_postmortem` (`store.py:417-425`): `UPDATE campaigns SET outcome=%s, defeated=%s WHERE campaign_key=%s` and, if `picked_ts` present, `UPDATE ... SET picked_ts=%s WHERE ... AND picked_ts IS NULL`.
- `write_interrupt` (`store.py:495-497`) calls `_campaign_id(key, faction)` with no map/radius/selector/difficulty/leader -> an interrupt that precedes the first decision of a campaign creates a row with those NULL; they are filled later only through the cache-hit UPDATE branch (never through the cold-cache INSERT ... DO NOTHING). 78 of 4,827 campaigns have `campaign_map IS NULL` and 78 have `first_decision_id IS NULL` (measured).
`campaign_key` = `campaign_uuid` when present else `"<faction>@<run_id>"` (`store.py:145-146`; run_id = basename of run dir = `run`, `store.py:65`, `common.py:180`, `manager.py:114`). 0 rows use the `@` fallback (measured).

### A.6 `decisions` (`pg_schema.py:53-63`)
`decision_id BIGINT identity PK, campaign_id BIGINT NN FK campaigns, ts DOUBLE, turn INTEGER, decision_seq INTEGER NN DEFAULT 0, policy TEXT, version_id BIGINT FK collector_versions, n_entities INTEGER NN, n_offers INTEGER NN, campaign_blob BIGINT FK blobs, world_blob BIGINT FK blobs, timings TEXT, income, settlements, allies, vassals, power_rank, lord_level DOUBLE`.
Indexes: `ix_dec_campaign(campaign_id, decision_id)`, `ix_dec_turn(turn)`, `ix_dec_ts(ts)`, `ix_dec_gains(campaign_id, decision_id, ts, turn, settlements, lord_level, allies, vassals)`, `ix_dec_turn_bounds(campaign_id, turn, decision_id)` (`pg_schema.py:145-154`).
Writers:
- `write_decision` (`store.py:222-231`): `INSERT ... RETURNING decision_id` with `n_offers=0`, `policy=None` (the only caller passes no policy: `decisions_stream.py:128`) -> `decisions.policy` is NULL on 100% of sampled rows (measured); `decision_seq` = recorder-lifetime counter (`decisions_stream.py:80,130`; max 21862 measured; never reset because `campaign_changed` always returns False, `decisions_stream.py:84-93`); `ts = snapshot["ts"] or time.time()`; `turn = int(camp.turn or 0)`; scalars via `_real_or_none` over `CAMPAIGN_SCALARS` (`pg_schema.py:164-165`, `store.py:231`); `version_id` NULL when `TW_CODE_VERSION` unset (6585/10345 sampled rows NULL, measured).
- `attach_options` (`store.py:270-271`): `UPDATE decisions SET n_offers=%s`.
- `attach_timings` (`store.py:279-280`): `UPDATE decisions SET timings=%s` (skipped when timings falsy, `store.py:276-277`).
Order per decision: INSERT (snapshot rpc) -> UPDATE n_offers (options rpc) -> UPDATE timings (pick rpc). Invariant check `LAYOUT_INVARIANT` (`pg_schema.py:279-281`, `store.py:804-805`) is read-only.

### A.7 `entities` (`pg_schema.py:65-69`)
`decision_id BIGINT NN, entity_seq INTEGER NN, context_kind TEXT NN, context_id TEXT NN, features_blob BIGINT NN FK blobs, PK(decision_id, entity_seq)`. No FK to decisions. Writer: `write_decision` `executemany INSERT` (`store.py:233-239`), one row per entity in list order (`entity_seq` = enumerate index); `context_id = str(e["context_id"])`; `features_blob = _blob(_dumps(e["state"] or {}))`. The `_blob` calls happen while the parameter list is built, i.e. before the executemany, inside the same transaction. Mean 5.5 entities per decision (56556/10345 sampled, measured); kinds campaign/hero/lord/province (measured).

### A.8 `offers` (`pg_schema.py:71-74`)
`decision_id BIGINT NN, offer_seq INTEGER NN, entity_seq INTEGER NN, action_id BIGINT NN FK actions, PK(decision_id, offer_seq)`; index `ix_offers_action(action_id)`. Writer `attach_options` (`store.py:248-273`): `SELECT context_kind,context_id FROM entities WHERE decision_id=%s ORDER BY entity_seq` to map options onto `entity_seq` (`store.py:250-252`, raises ValueError for an unknown entity `store.py:256-258`), per option `_action_id` (see A.4), `executemany INSERT INTO offers` (plain INSERT, no ON CONFLICT -> a second `options` rpc for the same decision raises UniqueViolation), then the `decisions.n_offers` UPDATE, commit. Cap `MAX_OFFERS_PER_DECISION = 2^20` (`pg_schema.py:4`, `store.py:263-265`). ~120 offers per decision (24.8M/207k, measured).

### A.9 `taken` (`pg_schema.py:76-83`)
`decision_id BIGINT PK, offer_seq, entity_seq INTEGER, action_id BIGINT, ts DOUBLE, executed SMALLINT NN, confirmed SMALLINT NN, counted SMALLINT NN, refusal TEXT, confirm_signal TEXT, confirm_before TEXT, confirm_after TEXT, latency_ms INTEGER, policy TEXT, timing TEXT, diagnostics TEXT, campaign_id BIGINT`. Indexes `ix_taken_ts`, `ix_taken_counted`, `ix_taken_agg(campaign_id, action_id, policy, refusal, counted, latency_ms, ts)`, `ix_taken_action` (`pg_schema.py:148-157`).
Writer `attach_taken` (`store.py:331-372`): `SELECT o.offer_seq,o.entity_seq,o.action_id FROM offers JOIN actions ... WHERE decision_id AND context_kind/context_id/action_type/action_key ORDER BY offer_seq LIMIT 1` (params are not part of the match), else `_action_id(...)` with `_dumps(params)`; then `INSERT INTO taken ... (SELECT campaign_id FROM decisions WHERE decision_id=%s) ON CONFLICT (decision_id) DO UPDATE SET <every column>` -- last writer wins. Called twice per decision: from the `pick` rpc with a placeholder `dict(pick, executed=False, confirmed=False, counted=False, refusal="awaiting_execution")` (`decisions_stream.py:186-189`) and from the `verification` rpc with the executor's result (`decisions_stream.py:194-197`). `finalize_stale_awaiting` (`store.py:510-516`, called at every store open `decisions_stream.py:111`) rewrites leftover `awaiting_execution` to `campaign_died` (77 such rows, measured).

### A.10 `offer_scores` (`pg_schema.py:85-90`)
`decision_id, offer_seq, score, exploit, rank, pct_global, gnn_impact, gnn_rank DOUBLE, PK(decision_id, offer_seq)`. Writer `attach_scores` (`store.py:293-329`): `SELECT o.offer_seq, a.* FROM offers JOIN actions WHERE decision_id` (`_seq_by_identity`, `store.py:284-291`, first offer_seq per identity wins via setdefault), then `executemany INSERT ... ON CONFLICT (decision_id,offer_seq) DO UPDATE SET <all six>`; scores whose identity is not among the offers are silently skipped (`store.py:303-304`). Fields listed in `SCORE_FIELDS` (`pg_schema.py:6`). Largest table: 22.4M rows, 2.6 GB (measured). 565/4138 sampled decisions have no offer_scores (measured).

### A.11 `offer_model_scores` (`pg_schema.py:92-95`)
`decision_id, offer_seq, model TEXT NN, score, rank DOUBLE, PK(decision_id, offer_seq, model)`. Same writer, from `s["models"]` (`store.py:307-310, 322-327`), `ON CONFLICT DO UPDATE`. Only model observed: `greedy_gnn` (measured; producer `advisor/policy.py:213-215`).

### A.12 `interrupts` (`pg_schema.py:97-106`)
`interrupt_id identity PK, ts, campaign_id FK campaigns, turn, kind TEXT NN, root, root_context, n_options INTEGER, options_json TEXT, chosen, chosen_context, executed, confirmed, counted SMALLINT, refusal, latency_ms, campaign_blob, world_blob, panel_blob FK blobs, policy`; index `ix_interrupts_campaign(campaign_id, interrupt_id)`. Writer `write_interrupt` (`store.py:482-507`): `_campaign_id` (0-5 UPDATEs or INSERT+SELECT), `_blob(camp)`, `_blob(world)` if truthy, `_blob(panel)` if truthy, single `INSERT`, commit. `kind` column = `row["screen"]` (renamed from the record's `kind` by `journal.log_interrupt`, `journal.py:204-207`); `counted` derived when absent (`store.py:486-488`). `panel_blob` NULL on 401/2169 sampled rows, `world_blob`/`campaign_blob` never NULL in sample (measured). The UI `tree` carried in the rpc payload is dropped (`interrupt_decisions` view exposes `NULL AS tree_json`, `pg_schema.py:245`).

### A.13 `rpc_requests` (`pg_schema.py:108-110`)
`rpc_id identity PK, req_id TEXT UNIQUE, kind TEXT NN, ts DOUBLE NN, payload TEXT`; index `ix_rpc_req_id(rpc_id)` (redundant with the PK, `pg_schema.py:160`). Writer `journal._ask` (`journal.py:77-83`): `INSERT` then `SELECT pg_notify('rpc_requests', req_id or kind)` on an autocommit connection (two statements, not atomic). `req_id` is non-NULL only for `snapshot/turn/hash` (`journal.py:173-201`); all `log_*` kinds insert NULL (`journal.py:204-232`). Deleter `journal.prune` (`journal.py:132-138`): `DELETE ... WHERE rpc_id<=%s AND ts<now-900` every 600 loop ticks (`decisions_stream.py:215-219`). 1,239 rows live, avg payload 34 KB for `options`, 38 KB for `pick`, 346 KB (max 970 KB) for `interrupt` (measured).

### A.14 `rpc_responses` (`pg_schema.py:112-114`)
`req_id TEXT PK, ts DOUBLE NN, decision_id BIGINT, payload TEXT, error TEXT`. Writer `journal.respond` (`journal.py:85-95`): `INSERT ... ON CONFLICT (req_id) DO UPDATE SET ts, decision_id, payload, error` + `pg_notify('rpc_responses', req_id)`. Called for `snapshot/turn/hash` success (`decisions_stream.py:132-135, 145-146, 150`) and for any failed request that had a req_id (`decisions_stream.py:211-213`). Deleter `prune`: `DELETE ... WHERE ts<cutoff` (`journal.py:137`).

### A.15 `postmortems` (`pg_schema.py:116-120`)
`postmortem_id identity PK, campaign_key, ts, run_dir, faction, turn INTEGER, outcome, defeated SMALLINT, reason, payload TEXT`. Writer `write_postmortem` (`store.py:403-427`): one `INSERT` (+ the two `campaigns` UPDATEs when `campaign_key` present), commit. `reason` = `ended_by` if str, else `_dumps(ended_by)` if truthy, else `error` (`store.py:414-415`; observed value `["end_turn_chosen","end_turn_chosen"]`, measured). `turn` = `turn_at_death or turns_played`.

### A.16 `diplomacy_events` (`pg_schema.py:122-124`)
`event_id identity PK, ts, campaign_key, turn INTEGER, kind, payload`; index `ix_diplo_ev(campaign_key, event_id)`. Writer `write_diplomacy_event` (`store.py:444-455`): `INSERT`, commit; `payload` = row minus `kind/turn/campaign_key/campaign_id/ts`. **`kind` is always `'diplomacy'`** (1483/1483 sampled rows, measured): `journal.read_requests` overwrites the body's `kind` with the rpc kind (`journal.py:108`), so the emitter's kind (`deal` / `pair_checkpoint` / `campaign_end`, `launcher/diplo_stream.py:58, 90`, `launcher/diplomacy_actions.py:93`, `launcher/interrupts.py:962, 1099`, `advisor/loop.py:324`) is lost and is not in the payload either.

### A.17 `ucb_picks` / `ucb_pick_rows` (`pg_schema.py:126-140`)
`ucb_picks(pick_id identity PK, ts NN, c, total_plays, campaign_map, faction, n, mean, explore, score, tied, blend, entropy, std, adjust)`; `ucb_pick_rows(pick_id, rank INTEGER, campaign_map, faction, n, mean, explore, score, chosen SMALLINT, blend, entropy, std, adjust, PK(pick_id, rank))`; index `ix_ucb_picks_ts`. Writer `write_ucb_pick` (`store.py:374-401`): `INSERT ucb_picks RETURNING pick_id`, `executemany INSERT ucb_pick_rows` (rank = 1-based list position), commit. The `k` and `scale` fields of the record (`advisor/session.py:180`) are not stored. 129 rows per pick in the latest pick (measured).

### A.18 Views (`pg_schema.py:168-276`)
`decision_points` (joins blobs `z` for campaign/world), `entity_snapshots` (`snapshot_id = decision_id*65536 + entity_seq`), `action_offers` (`offer_id = decision_id*2^20 + offer_seq`, left-joins scores and the `greedy_gnn` model row as `ggnn_score/ggnn_rank`), `action_taken`, `turn_bounds` (MIN/MAX decision per campaign+turn), `turn_open`, `turn_close`, `interrupt_decisions`, `start_counts`, `campaign_gains`. Packing constants `MAX_ENTITIES_PER_DECISION = 2^16`, `MAX_OFFERS_PER_DECISION = 2^20` (`pg_schema.py:3-4`), enforced at `store.py:214-216, 263-265`.

### A.19 Statement count and order per recorded decision (happy path snapshot -> options -> pick -> verification)

Recorder store connection, one transaction per bullet:
1. `write_decision` (`store.py:204-246`): 5 conditional `UPDATE campaigns` (warm cache) | INSERT+SELECT (cold); `SELECT blobs` [+INSERT] for campaign; same for world; `INSERT decisions RETURNING`; per entity `SELECT blobs` [+INSERT]; `executemany INSERT entities`; `UPDATE campaigns first/last/turns`; COMMIT. ~ 10 + 2E statements with E entities.
2. `attach_options` (`store.py:248-273`): `SELECT entities`; per option with a cold action cache `INSERT actions ON CONFLICT DO NOTHING` + `SELECT action_id` (2 statements; for `move` options effectively always, since their params are unique); `executemany INSERT offers`; `UPDATE decisions n_offers`; COMMIT.
3. `attach_scores` (`store.py:293-329`): `SELECT offers JOIN actions`; `executemany INSERT offer_scores ON CONFLICT DO UPDATE`; `executemany INSERT offer_model_scores ON CONFLICT DO UPDATE`; COMMIT.
4. `attach_timings` (`store.py:275-282`): `UPDATE decisions timings`; COMMIT.
5. `attach_taken` placeholder (`store.py:331-372`): `SELECT offers JOIN actions LIMIT 1`; `INSERT taken ON CONFLICT DO UPDATE`; COMMIT.
6. `attach_taken` verification: same two statements again (+ `_action_id` when the taken action is not an offer, e.g. forced `end_turn` `advisor/loop.py:760-761` or `noop` `advisor/loop.py:751-755`); COMMIT.
Steps 3-5 come from a single `pick` rpc row (`decisions_stream.py:182-193`), so one rpc row = three commits.

Recorder journal connection (autocommit, `journal.py:26-41`) per decision: `SELECT rpc_requests WHERE rpc_id>%s` per loop tick (`journal.py:101-103`); `INSERT rpc_responses ON CONFLICT` + `pg_notify` once for the snapshot (`journal.py:89-95`).

Recorder transient connections per snapshot (inside the measured `store_ms`, `decisions_stream.py:125-134`): `_sync_reference` calls `gameref.have_faction_tech`, `gameref.have_subtypes`, `gameref.region_count` (`decisions_stream.py:53-55`) -- each opens `pg.connect(autocommit=True)`, runs `ensure` = the 12-statement reference DDL (`gameref.py:57-63, 13-54`), one SELECT, and closes (`gameref.py:159-193`). That is 3 connects + 39 statements per decision on every snapshot.

Advisor journal connection per decision: `INSERT rpc_requests` + `pg_notify` x4 (snapshot, options, pick, verification), `SELECT rpc_responses` polls (`journal.py:146-147`), and the read-back `read_decision` (`store.py:574-587` + `_entities_and_offers` `store.py:549-572`: 3 SELECTs) on the advisor's read-only store (`journal.py:44-49`).

### A.20 Error handling and connection lifecycle
- Store methods have no try/except; exceptions propagate to `decisions_stream.py:205-213`: error counted, `ctx.on_error` (errors.log, `manager.py:90-104`), a `decisions_error` row in `decisions_stream.jsonl`, and `journal.respond(..., error=...)` only when the request had a `req_id` -- so failures of `options/pick/verification/interrupt/diplomacy/ucb_pick/postmortem` are never reported back to the advisor.
- No rollback is issued. The store connection is non-autocommit, so after a server-side error (e.g. UniqueViolation from a repeated `attach_options`) the transaction stays aborted and every later statement on `store.con` fails with InFailedSqlTransaction until the process restarts (psycopg3 semantics; not runtime-tested here). After a Python-side exception raised between statements without a server error (e.g. `store.py:256-258` after the SELECT at 251), the open transaction is simply continued by the next call and committed with it.
- Store open: once per recorder lifetime (`decisions_stream.py:100-115`; reopened only if `ctx.out_dir` changes, which it never does -- `Ctx.out_dir` is fixed at `manager.py:26-35`). Closed at loop exit (`decisions_stream.py:226-228`) or replaced (`decisions_stream.py:102-103`). No reconnect logic.
- Journal connection: thread-local, opened lazily on first use (`journal.py:26-41`), never reconnected; a dropped connection makes `read_requests` raise into the outer handler (`decisions_stream.py:220-223`), which backs off 5 s and retries with the same dead object forever.
- `pg.connect` (`pg.py:49-64`): host/port/db/user/password from `TW_PG_*` env with defaults `127.0.0.1:55432/tw_stack/tw` (`pg.py:33-37`); no `application_name`, no connect timeout, no keepalives; `readonly` => `SET default_transaction_read_only = on`.

## B. The record shape

The record is `collect.snapshot(bus, active)` (`collect.py:1671-1865`) = `{"ts", "campaign", "world", "entities", "profile"}` (`collect.py:1864-1865`). Every Lua reply comes back through `twcontrol.lua`'s `log()` (`twcontrol.lua:61-71`) as one JSON line `{seq, cmd, ..., ts, clk, try_fails}` encoded by `encode` (`twcontrol.lua:19-36`): Lua numbers are formatted `%.14g` (so integral values become Python `int`, others `float`, NaN/inf -> `null`), `nil`/`NULL` -> `null` -> Python `None`, an **empty Lua table encodes as `{}`** (object, never `[]`). `eval` replies carry the Lua return value in `result` (`twcontrol.lua:495-507`); every `collect.py` eval snippet returns a delimiter-joined string that Python re-splits.

Three bus waves (`collect.py:1674-1679` wave A, `1744-1770` wave B in chunks of 14, `1820-1828` wave C) plus `campaign_map` (`collect.py:158-168`, one `eval`, cached per uuid) and `_lord_pools` (`collect.py:1836`, one `eval` when regions non-empty). Bus batch = one appended block of `<seq> <channel> <payload>` lines (`bus.py:313-334`) and a poll of `twcontrol.jsonl` from the recorded offset (`bus.py:342-361`); the mod polls `commands.txt` every 20 ms (`twcontrol.lua:6, 1377-1430`).

Notation: `key: type` -- Lua source -- destination. Destinations: **CB** = campaign blob (`decisions.campaign_blob`, `store.py:230`), **WB** = world blob (`decisions.world_blob`, `store.py:230`), **EB(kind)** = entity features blob (`entities.features_blob`, `store.py:238`), **col** = typed column. `_num` = `float(x)` or `None` (`collect.py:69-73`); `_key` = None for `""/"nil"/"None"` (`collect.py:306-308`).

### B.1 Top level
- `ts: float` -- `time.time()` at end of collect (`collect.py:1864`) -- col `decisions.ts` (`store.py:228`).
- `campaign: dict` -- see B.2 -- CB (`_dumps(camp)`) + cols; also the base of the `campaign` entity (B.6).
- `world: dict` -- see B.3 -- WB (`_dumps(world)`).
- `entities: list[{context_kind, context_id: str, state: dict}]` -- B.4-B.6 -- one `entities` row + EB each; `n_entities` col.
- `profile: dict` -- `collect.py:1672, 1680, 1682, 1771, 1829, 1838, 1857-1862` -- NOT stored in Postgres; emitted only into `decisions_stream.jsonl` (`decisions_stream.py:140`). Keys: `wave_a_ms, campaign_state_engine_ms, wave_b_ms, wave_c_ms, lord_pools_ms, _entities, _lords, _heroes, _regions, _wave_b_cmds, _wave_c_cmds`.

### B.2 `campaign` (CB)
Parsed by `_parse_campaign` (`collect.py:247-273`) from the `|`-joined string of `_LUA_CAMPAIGN` (`collect.py:171-212`), index p[i]:

## C. Blob mechanics
- Split: `write_decision` makes exactly 2 + n_entities blobs: `_dumps(camp)`, `_dumps(world or {})`, `_dumps(e["state"] or {})` per entity (`store.py:230, 238`); `write_interrupt` makes 1-3 (`store.py:503-505`).
- Canonicalisation: `_dumps = json.dumps(o, default=str, sort_keys=True, separators=(",", ":"))` (`store.py:58-59`). Non-JSON values are stringified by `default=str`; key order sorted; no whitespace; floats printed by Python's repr (e.g. `1.0`, `0.6865234375`).
- Hash: `hashlib.sha256(text.encode("utf-8")).hexdigest()` (`store.py:113`); `n = len(text)` = character count, not bytes (`store.py:121`; `n = length(z)` on 2000/2000 sampled rows, measured).
- Compression: **none**. `blobs.z` is the plain UTF-8 JSON text (`store.py:121`; measured `left(z,80)` starts `{"acted":true,...`). No zstd/zlib anywhere in `decisions/`.
- Dedup: by `sha` UNIQUE with SELECT-then-INSERT plus a process cache of at most 4096 entries cleared wholesale when exceeded (`store.py:114-127`). Effect measured on `decision_id % 20 = 0`: campaign blobs 10344 distinct / 10345 decisions, world blobs 9980 / 10345, entity blobs 54616 / 56556 -- dedup removes ~3.4% of entity blobs and ~0% of campaign blobs (treasury/read_failures/x-y make each unique). Blob size p50 10.2 KB, p90 16.2 KB, max 35.5 KB over the last 5000 blobs (measured); `blobs` totals 949k rows / 2.4 GB including TOAST (measured).
- References: `decisions.campaign_blob`, `decisions.world_blob` (`store.py:224, 230`), `entities.features_blob` (`store.py:236-238`), `interrupts.campaign_blob/world_blob/panel_blob` (`store.py:492, 503-505`); all FK to `blobs(blob_id)` (`pg_schema.py:59-60, 68, 103-105`).
- Deletion: never. There is no DELETE/UPDATE on `blobs` in the tree; `retention.py` only removes files under `D:\twdata` (`retention.py:23-67, 90-153`) and lists dead sqlite files (`retention.py:55-65`).

## E. Failure semantics
Kill of the recorder (manager) between statements, per decision:
- Inside `write_decision`: nothing persists (single uncommitted transaction incl. new blobs); the advisor's `_await` times out after 180 s (`journal.py:173-177, 141-166`) and raises.
- After `write_decision` commit but before `journal.respond` (`decisions_stream.py:128-135`): an orphan `decisions` row with `n_offers=0`, `timings NULL`, entities+blobs present, no `rpc_responses` row -> advisor timeout as above. Such rows are indistinguishable from advisor-side abandonment (29/4138 sampled decisions lack `timings` and 29/4138 lack a `taken` row, measured).
- After `options` commit: offers + `n_offers` set, no scores/timings/taken.
- Within the `pick` rpc: `attach_scores` commit, `attach_timings` commit, `attach_taken` commit are three separate transactions (`decisions_stream.py:184-189`); a kill between them leaves scores without timings, or scores+timings without a `taken` row.
- After the placeholder `taken` but before `verification`: `refusal='awaiting_execution'`; on the next recorder start `finalize_stale_awaiting` relabels it `campaign_died` (`store.py:510-516`, `decisions_stream.py:111`). If the advisor died instead, the row keeps `awaiting_execution` until the recorder restarts.
- `write_interrupt/diplomacy/ucb/postmortem`: single transaction each -> all-or-nothing, but `write_postmortem`'s `campaigns` UPDATEs are in the same transaction as the INSERT (`store.py:409-426`).
- `gameref.write` runs on an autocommit connection: DELETE-then-INSERT per faction/subtype (`gameref.py:101-108, 126-152`) -> a kill leaves the reference partially rebuilt; the next snapshot's `_sync_reference` re-collects what is missing (`decisions_stream.py:53-59`).
Restart/resume:
- Watermark = `MAX(rpc_id)` at store open (`decisions_stream.py:112`, `journal.py:120-126`): every request row not yet processed at the kill is **skipped**, never replayed; the advisor waiting on a `snapshot/turn/hash` times out; fire-and-forget kinds (`options/pick/verification/...`) are lost silently and pruned 900 s later (`journal.py:129-138`).
- Requests are processed strictly in `rpc_id` order; `decision_id` is carried in the payload, so a lost `options` row followed by a `pick` row makes `attach_scores` skip every score (no offers) and `attach_taken` create the action via `_action_id` with `offer_seq NULL`.
- No journal, no per-decision idempotency key: a resent `snapshot` creates a new decision; a resent `options` raises UniqueViolation (and poisons the store connection, A.20); `attach_scores`, `attach_timings`, `attach_taken`, `rpc_responses` are idempotent upserts; `interrupts/diplomacy_events/ucb_picks/postmortems` duplicate on resend; `blobs/actions/campaigns/collector_versions` dedup by natural key.
- `synchronous_commit = off` on both recorder connections (`store.py:75`, `journal.py:37`): a Postgres crash can lose the last commits even though the client saw them succeed.
- Recovery of a wedged recorder is external: `runctl.harness_tick` (`runctl.py:374-434`) kills and relaunches the whole stack when the session log shows no progress for 1800 s (`runctl.py:275-278`), with a 1800 s cooldown; `kill_recorder` = Stop-Process on `manager.py` (`runctl.py:71-82, 101-102`) -- an abrupt kill, no drain.
- Bus-side: `commands.txt` and `twcontrol.jsonl` are truncated at every manager start (`manager.py:244-267, 312`); the mod re-seeds `last_seq` from its saved value or the file (`twcontrol.lua:1400-1403, 1620-1623`); `Bus._max_existing_seq` seeds the client (`bus.py:127, 149-162`).

## F. Process topology (Postgres connections on this path)
1. **manager.py process** ("recorder", spawned by `runctl.start_recorder` `runctl.py:109-117` as `.venv python -u manager/manager.py --shots N --dev`, killed by matching `manager.py` in the command line `runctl.py:101-102`). Threads (`manager.py:225-241`):
   - `decisions` thread (`decisions_stream.run`): (a) `DecisionStore.con` write connection, non-autocommit, `synchronous_commit=off`, lives for the process (`store.py:74-75`); (b) `journal._local.con` autocommit + `LISTEN rpc_requests` + `LISTEN rpc_responses`, `synchronous_commit=off`, thread-local, lives for the process (`journal.py:26-41`); (c) transient autocommit connections: 3 per snapshot from `gameref` probes and 1 more per reference write (`gameref.py`), 1 per uuid change from `workspace.tag_campaign` when `TW_EXPERIMENT_ID/TW_SEGMENT_ID` are set (`decisions_stream.py:24-35`, `workspace.py:229-240`, also runs the 12-statement `app` DDL `workspace.py:98-114`), 1 once from `collect._merc_flavors` (read-only, `search_path=reference`, `collect.py:535`), and `bus_stats` flushes every 200 bus calls / 10 s (`bus/bus_stats.py:15-16, 169-183`, `search_path=bus`, enabled by default `bus_stats.py:29-33`).

   - Other optional threads (input/shots/ui-capture/actions/logs) are not on this path.
2. **advisor session process** (`advisor/session.py`, spawned `runctl.py:148-187`): `journal._local.con` (autocommit, LISTEN both channels) and `journal._local.store` (read-only `DecisionStore`, `journal.py:44-49`, `store.py:70-73`) per thread; plus transient read-only connections in `session.py:99, 121, 205, 734, 994` and `bus_stats` flushes. ## G. Timings
- `rpc_responses.payload` for a snapshot (`decisions_stream.py:121-135`): `pickup_lag_ms` = loop pickup time minus `rpc_requests.ts`; `collect_ms` = `collect.snapshot` wall time (t1-t0); `store_ms` = t2-t1 = `_sync_reference` (3 gameref probe connections + optional reference collect/write) + `campaign_changed` + `store.write_decision` -- i.e. `store_ms` is not pure store time. Measured recent values: collect 378-410 ms, store 77-212 ms, pickup 0.
- `decisions.timings` (D.7): advisor-side; `roundtrip_ms` = `t_received - t_request` around `request_snapshot` (`loop.py:554-555`, `journal.py:175-183`), which includes the recorder round trip and the `read_decision` read-back; `score_ms` = `pol.choose`; `trace_ms` = trace write; `housekeep_ms` = gap between the previous action's end and this request; `housekeep_parts` = per-stage ms of the previous iteration (`loop.py:456, 510, 572, 581, 586, 606, 659, 665, 668, 674`); `collect_ms/store_ms/pickup_lag_ms` copied from the rpc reply (`journal.py:184-186`).
- `taken.timing` (D.4) and `taken.latency_ms`: executor-side execute/confirm phases (`cco_actions.py:158-257`).
- `interrupts.latency_ms`: click-to-resolution time from `_record_choice` callers (e.g. `interrupts.py:444, 636, 666`).
- `decisions_stream.jsonl` rows (not in Postgres): `decisions_point.ms` = whole request handling incl. respond (`decisions_stream.py:136-140`), `profile` = collector wave breakdown (B.1), `gameref.ms` (`decisions_stream.py:72-73`).
- `common.waitlog`/`wait` stderr lines (`common.py:8-17`) for `recorder_rpc` (`journal.py:150, 164`), `batch_reply_poll` / `send_reply_poll` (`bus.py:274, 288, 349, 363`), `decisions_poll` (`decisions_stream.py:225`).

## H. Simplicity / fallback / dead-code notes (facts only)
1. `campaign_changed` returns False on both paths (`decisions_stream.py:87, 93`), so `seq = 0` at `:127` is unreachable and `decision_seq` counts across campaigns for the recorder's lifetime (max 21862, measured).
2. `decisions.policy` is never written (no caller passes it, `decisions_stream.py:128`); 0 non-NULL in sample.
3. Five conditional `UPDATE campaigns` statements execute on every decision once the campaign cache is warm (`store.py:150-177`); all are no-ops after the first decision.
4. `_sync_reference` opens 3 connections and runs the reference DDL 3 times per snapshot (`decisions_stream.py:53-55`, `gameref.py:57-63, 159-193`); its cost is booked under `store_ms`.
5. The campaign scalars are stored twice per decision: CB and EB(campaign) (`store.py:230, 238`; `collect.py:1852`).
6. `actions` has 5.1M rows because `params` (incl. `reach_rays/reach_max/sample_index` for `move`) is part of the UNIQUE key (`pg_schema.py:43`, `options.py:72-75`); 4.89M are `move` (measured). The action cache is cleared wholesale at 200000 entries (`store.py:140-141`), the blob cache at 4096 (`store.py:124-125`).
7. Blob sha-dedup buys ~3% on entity blobs and ~0% on campaign/world blobs (measured, C).
8. `_mask_ruin_owners` on `hostiles` is a no-op because ruin settlement rows are filtered out first (`collect.py:1695-1698`); `world_state(bus, prof)` stage timings (`collect.py:417-426`) are never collected (only caller passes no `prof`, `decisions_stream.py:154`).
9. `journal.read_requests` envelope overwrite (`journal.py:108`) destroys the diplomacy emitter kind (A.16), replaces record timestamps for interrupt/diplomacy/ucb/postmortem rows with the rpc insert time, and leaks `kind/req_id/rpc_id` into `postmortems.payload` (D.10).
10. `store._dumps(None)` stores the string `null` in `taken.confirm_before/confirm_after/timing` (D.2, D.4) instead of SQL NULL.
11. The `taken` row is written twice per decision (placeholder + verification) and every column is overwritten by the upsert (`store.py:352-360`).
12. `ix_rpc_req_id ON rpc_requests(rpc_id)` duplicates the primary key (`pg_schema.py:160`).
13. `interrupt_decisions` exposes `NULL AS tree_json` (`pg_schema.py:245`); the tree is shipped through `rpc_requests` (avg 346 KB per interrupt row, measured) and discarded.
14. `write_interrupt` creates campaign rows without map/radius/selector/difficulty/leader (`store.py:495-497`); 78 such rows exist (measured).
15. `chars/setts/hostiles/trait_progress` reply `try_fails` are never folded into `read_failures` (`collect.py:1685, 1693-1696` bypass `_bres`).

24. The manager's `events` thread also drives its own `Bus()` and calls `collect.campaign_state` every 20 s (`logs/events_stream.py:94-118`); it shares the module-global `collect._TRY_FAILS` list with the decisions thread without a lock (`collect.py:26-44`), so its Lua read failures are folded into the next decision's `campaign.read_failures`.
