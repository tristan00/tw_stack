## 4. The 16:45 breakage — what actually broke (campaigns 14–40)

Verified chain, each step evidence-cited; the adversarial pass corrected two wrong first-draft
theories (see end of section).

1. **Onset is in-game UI state, not the bus.** Campaign 14 (Bordeleaux) played turns 1–2 normally.
   In turn 3, `hud_campaign` vanished 6× with `ui_hiding=True` while the bus still answered
   (forced UI restore seq 47204 returned a full result); `end_turn` was then **silently refused
   twice** — the same signature as c3/c14 in §2A. The game's 253 MB script log stops at 16:42:53;
   a 16:46 screenshot shows a frozen in-campaign screen with a stuck enemy-army tooltip. The first
   fatal client timeout is the recorder's snapshot seq 47477 at 16:45:30.
2. **Every subsequent relaunch actually worked game-side.** Across 26 kill→relaunch cycles,
   `twcontrol.jsonl` contains 26 `frontend_armed` rows and **25 `started (fresh:true, turn:1)`
   rows**; each attempt produced a ~76 MB campaign script log; post-mortem live probes got roots
   answers in 21/26 and eval answers in 24/26; 9 of the 11 "campaign did not load within 360s"
   campaigns were **loaded and at turn 1** when probed. The final "failed" campaign (slot 40,
   Avelorn) is still running right now, fully playable — pid 44804, left untouched.
3. **The replies were unmatchable: seq corruption.** In the terminal window, 97 of 455 seq-bearing
   replies in `twcontrol.jsonl` carry a seq with the **leading digit stripped** (real seqs were
   46xxx–47xxx; the mangled ones are <10000). Every one of 14 sampled timed-out seqs (47507,
   47546, 47584, …) exists in the file as `seq-minus-leading-4` **with a correct, complete result
   payload** — the game executed the command and filed the answer under the wrong number, and
   `bus.py` matches replies by exact seq, so the client times out. [PROVEN as data]
4. **Mechanism hypothesis** [LIKELY, not proven]: `twcontrol.lua`'s byte-offset tail cursor
   (lines ~791–811) can begin a read one byte into a line (dropping the seq's first digit), and the
   truncation-resync heuristic (`file_max < last_seq → last_seq = 0`, lines ~813–823) lets the
   mangled-seq command execute. The permanent phase begins exactly at the first cycle after
   session `_trim_bus` truncated `twcontrol.jsonl` (16:47 boundary) while `commands.txt` (16.8 MB,
   under the 64 MB threshold) was **not** truncated — the client kept seeding its counter from the
   47k-line command file while the game-side cursor state crossed a trim it half-expected.
   Sporadic same-signature timeouts existed all day and self-recovered; why it became persistent at
   16:47 is the unproven part. This wants a targeted repro, not a guess-fix.
5. **Why 26 campaigns burned instead of 3:** the two shapes strictly alternate —
   **L** "did not load within 360s" (11×, 415–470s: ~100s boot + the full 360s `load_timeout` in
   bus_launcher.py) and **T** "loads, HUD reached, first recorder eval times out" (13×, 140–178s)
   plus 2 direct variants — and `session.py:277-286` increments `launch_failures` only on
   "did not load" errors **and resets it to zero on any other error**. The A/B/A/B pattern kept the
   counter ≤1 forever. Cost: 8,011s. Separately: `CcoFrontendRoot.StartCampaign` returns **Void**
   (fire-and-forget per CA's own CCO reference) — there is no error channel on that call, so the
   client's only truth is the reply stream that was corrupted.
6. **Faction identity is falsified as a cause** — the failed set contains base-game and free lords
   (Queek, Kairos, Tiktaq'to, Alberic) while paid-DLC lords succeeded the same session; no static
   trait in `startable_factions.json` separates the sets; Steam's appmanifest can't even express
   WH3 DLC ownership (all content ships in the base depot).
7. **The new dump code is cleared** [PROVEN]: authored 32s before session start, 440 dumps with
   zero failures, heaviest activity (86 dumps in c10, max tree 3,479 nodes = 4.3% of budget) hours
   before the breakage; last dump completed 16:40:03, ≥15 successful bus round-trips after it, none
   in flight at first failure; essentially zero dump activity during the broken phase (one 50-node
   dump at 18:29 — which **succeeded**, further proof the bus intermittently delivered).

Corrections the adversarial pass made to the first-draft story (kept here so nobody re-derives the
wrong version): "twcontrol.jsonl 0MB = game-side writer dead" is a `%.0fMB` **rounding artifact**
(the writer demonstrably wrote every cycle); and "retraining stalled — rows never rose" is
**intended once-per-batch behavior** (commit 9926acd, same day) — the per-campaign header line
"killing the game now, before retraining" is stale phrasing, a cosmetic report item only.

## 7. What could be made faster — proposals only, nothing implemented

Ranked by measured cost. Each needs the operator's go and the standard 10x40-vs-baseline test.

1. **Make the breaker see the alternation (8,011s this session).** `launch_failures` resets on any
   non-launch error; count *consecutive campaigns without a played turn* instead of consecutive
   "did not load" strings, and the session stops after 3 broken cycles instead of 26. Smallest
   change with the largest measured payoff.
2. **Reply-seq integrity (same 8,011s, the actual disease).** First a targeted repro of the
   [LIKELY] cursor/trim mechanism; candidate mitigations to *evaluate* (not chosen): trim both bus
   files together, ignore-and-rescan on unmatched seq (client-side full-line rescan before
   declaring timeout — the payloads were there), or a seq echo/checksum in the reply. Needs its own
   test session; touching twcontrol.lua blind is how engines hang.
3. **Inter-turn sweep budget (7,147s, 52% of play).** Median 46.6s/turn of resolve waiting. The
   sweep's fixed settles and re-walks are worth profiling per step — even −20s/turn ≈ −48min per
   145 turns. Evidence to collect first: per-step timing inside `resolve()` (see §8.6).
4. **Defeat postmortem (510s).** A constant 63.8s × every defeat, plus 27 doomed watchdog digest
   probes (~30s each) fired into a modal that provably pauses the tick. Skip digest probes once a
   defeat root is on screen; postmortem after the modal is acknowledged, not before.
5. **Launch path (~2,975s).** ~110s/launch is mostly game boot (irreducible), but the ESC-storm
   outliers (24/31 presses, +60–80s) and the 360s `load_timeout` paid in full 11× by campaigns that
   *had already loaded* (per §4.2 the game logged `started`; a client-side rescan on timeout —
   proposal 2 — collapses those 360s waits to ~0).
6. **popup_pre_battle dump dedupe (disk only, not time).** 70% of dump bytes are 3–5× repeats of
   the same battle; the content-hash memo already dedupes identical trees, so these differ by
   volatile nodes — a per-battle key would cut ~19 MB/session. Cosmetic; only if volume ever matters.

## 8. What data we should be collecting — proposals

1. **Reply-seq integrity monitor.** The recorder (sole bus owner) cheaply asserts
   `reply.seq ∈ issued-seqs`; on mismatch, log the raw line + cursor position + last trim time.
   This turns the next occurrence of §4 from 2h14m of mystery into one log line. Also: log
   `_trim_bus` events with byte offsets (it currently logs sizes only).
2. **`end_turn` refusal forensics (the §2A family — 3 of 5 stucks).** At refusal time, capture the
   engine's pending-action state: `CcoCampaignPendingActionNotificationQueue` contents, whether
   notifications are suppressed, and `cm:whose_turn_is_it()` — plus dump all roots (the choke-point
   net already fires; add the *absence* record: "no odd roots at refusal"). The wounded-LL
   correlation (2/3 cases) is checkable from data already recorded if we log the pending queue.
3. **`ally_attacked` outcome data — needs a handler decision first.** Both options are
   consequential (join = enter a war; decline = break alliance + ~30–50-turn reliability hit).
   Options: (a) uniform random join/decline like occupation/captives, recorded to
   `interrupt_decisions` so the model can learn it later; (b) fixed policy. Operator's call. Until
   then every occurrence is a dead campaign — 2 campaigns killed by this screen class in two
   sessions (both dumps now on disk).
4. **Outgoing diplomacy failure evidence (47/0).** At each `failed_at`, dump the panel tree (the
   predismiss net catches some already) plus the specific missing control id searched for. Three
   distinct failure points are already distinguishable (`faction_selection` 10, `deal_selection`
   18, `ai_would_refuse` 19) — the first two are harness defects, the third may be legitimate.
5. **Recruit name mapping.** `recruit_lord` 6/37 and `recruit_unit` 53/103 fail on raw-key vs
   card-id mismatches (`sorceress_death` not in agent types; `corsairs_0@local` vs `@global`).
   Record, per settlement snapshot, the panel's actual card ids next to the offered raw names —
   the mapping table falls out of one session of data. (Known deferred issue; now quantified.)
6. **Per-step timing inside `resolve()`/inter-turn sweeps** (`step, root, seconds` triples) to
   ground proposal 7.3 before touching anything.
7. **Outcome taxonomy fixes (report hygiene).** c10 was a process CTD recorded as `stuck`;
   `_totals` zeroes turns/actions for non-completed campaigns; `run_dirs` lists 27 duplicates;
   the retrain JSON log line prints unbalanced. All cosmetic, all misleading at 2am.
8. **Frontend preflight data.** CA's own gate is `CcoFrontendFactionLeader.IsOwned` /
   `LockedReasonText` ("Empty if nothing stopping starting the campaign") — the harvest never
   queried it. One pass at frontend per session, recorded alongside `startable_factions.json`,
   removes a whole class of "was it even startable?" doubt (this session: faction identity was
   falsified as the failure cause, but the preflight makes that falsification free next time).
