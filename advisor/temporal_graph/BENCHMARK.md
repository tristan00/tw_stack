**Temporal graph construction evidence — 2026-09-08**

Cleanup verification: 146 focused graph, tuning and sequence-worker tests passed. A fresh CPU-only benchmark completed in 23.27 seconds with two repeats, retained 47 distinct topologies from 48 recipes, and measured a 4.82× speedup over the scalar scoring/selection reference with identical endpoints. The detailed tables below record the original five-repeat measurements.

The standalone constructor generated 47 distinct structural fingerprints from 48 recipes on identical input, exercised all eight graph layouts, and changed graph structure when each of its eight controls was perturbed. Tests cover causal cutoffs, both temporal clocks, no current selected-action leakage, query-order/chunking invariance, current/full graph parity, packing preservation, group arity, memory-cache invalidation, explicit resource failures, and an independent scalar nearest-neighbor reference. **Measurement conditions**

Windows 11, Intel64 Family 6 Model 198 Stepping 2, 24 logical CPUs, Python 3.13.4, NumPy 2.5.2. All construction runs used CPU arrays; no model, database, game, or GPU was loaded by the benchmark. The final benchmark was run without concurrent test execution and took 35.43 seconds.

Histories are reproducibly generated by `examples.campaign`, seed 17, with six numeric features, stable/changing streams, four decisions per turn, shared entities, direct references, spatial positions, and one selected-action event per decision. The input includes the final selected-action event to verify that the scorer excludes it at the current cutoff. Query counts are at most 32. These fixtures exercise graph mechanics; they do not pretend to be captured campaigns.

Each scaling case uses observation nodes, mixed affinity, degree 8, 64 candidate slots, query degree 16, receiving blocks of 256, and a lookback retaining its full prefix. Cold time includes materialization, index construction, query attachment, candidate retrieval, scoring, selection, and output assembly around the complete function call. Prepared `History` creation is reported separately in the raw JSON. Cached times are the median of five complete repeated calls on the same immutable prefix/query objects. Their p95 is only a small-sample observation.

**Retrieval quality limits**

On the same small prefix, exact all-pairs scoring provides a comparator for the fraction of exact top-8 edges recovered by sparse retrieval:

| Affinity | 32 proposals | 64 proposals | 128 proposals |
|---|---:|---:|---:|
| Similarity | 33.1% | 47.9% | 65.1% |
| Contrast | 22.8% | 35.6% | 53.7% |
| Mixed | 34.5% | 52.6% | 73.0% |
| Geometric | 35.6% | 52.5% | 74.1% |

This is a material limitation: the default bounded pool misses many edges that exhaustive affinity selection prefers. It is a fast, diverse proposal mechanism, not an exact nearest-neighbor index. The result supports tuning candidate budget and improving retrieval before making model-quality claims. Exact top-k agreement is not itself reward quality, but poor coverage must not be hidden behind fast construction numbers. `exhaustive=True` remains available within the explicit pair-work ceiling.
